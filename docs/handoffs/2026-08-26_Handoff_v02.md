### The glossary decision

Tip copy lives in `src/ui/glossary.ts`, 18 entries, each with a short tip and the
methodology section that covers it in full. It is not inlined into components.

The reason is drift: the methodology page and the tooltips say the same things,
and prose duplicated into components goes stale silently when a rate changes.
Keeping it in one module also makes the copy testable, and four tests hold it:

- No orphan entry that nothing references, and no component referencing a term
  the glossary does not define. Component sources are read with
  `import.meta.glob`, so this needs no `@types/node` and no new dependency.
- No em dash, per the house style rule.
- No tip too long to read in a popover.
- No tip naming a methodology section that is not actually on the page.

That last test is the useful one. It means a tip can never promise a section that
was renamed or removed.

### Why it is a disclosure, not a tooltip

`InfoTip` opens on click. A hover tooltip is unreachable by touch and awkward by
keyboard, and these explanations are load-bearing rather than decorative: a
reader who cannot open one cannot understand the number. It carries
`aria-expanded` and `aria-controls` because it is toggled and holds a heading,
which is disclosure behaviour and not what `role="tooltip"` describes. Panel ids
come from `useId`, since the same term is explained in more than one place and
two triggers pointing at one id would be a lie.

## How UI work gets verified here

This is the finding worth carrying forward, and it cost most of the session to
reach.

**`tools/screenshot.sh` and `tools/screenshot.mjs` already existed** for the
README image, with `playwright-core` in `tools/node_modules` and a cached
Chromium. To check an arbitrary view, point `screenshot.mjs` at a running dev
server rather than at a build:

```
node tools/screenshot.mjs http://localhost:5173/ /tmp/shot.png \
  "$(find ~/.cache/ms-playwright -name chrome -path '*chrome-linux*' | sort | tail -1)"
```

Two traps, both hit this session:

1. ESM ignores `NODE_PATH`. `screenshot.mjs` resolves `playwright-core` by
   directory walking from its own location, so a copy of it outside the repo
   tree must import by absolute path.
2. `vite preview` cannot be used, which the script header already documented.

### What driving it caught

Three defects shipped in #57 with all 468 tests passing, because none is visible
from the DOM:

| Fault | Cause |
| --- | --- |
| Tip text in all caps | Card headings and table headers set `text-transform: uppercase`; the panel inherited it |
| Orphaned `?` markers on their own line | A label filling its column pushed the trigger to the next line |
| The ratio panel covered `0.908` | It opened from the heading, over the figure it explained |

The first was the bad one: it made the tooltips harder to read than no tooltips
at all. **A green suite says nothing about whether a UI change looks right.**

### Known issues

The tooltip panel is absolutely positioned, so a scrolling ancestor can clip it.
The only such ancestor is `.table-scroll`, where the panel opens downward over
the rows and fits inside them at any usual range. A two-row table would clip it.
Recorded as a comment in `src/index.css`; the alternative was CSS anchor
positioning for a top-layer panel, which was not worth it.

## Next actions

1. **#54 basic and advanced modes.** The owner's stated pain is that the app
   feels advanced on open, and this is the direct answer. Basic is year,
   province, lead country and one income; advanced adds the basis selectors, the
   range, assumptions, employer cost, the working, the table and the remaining
   charts. The mode rides in the share link. The constraint that matters: basic
   must not become "trust me", so it keeps the footer and a visible route into
   the working.
2. **#55 the lead-country switch.** The larger piece, and the one that answers
   "very Canada heavy" structurally. Two decisions are already recorded in the
   issue: the engine's `ratio` stays Austria over Canada whatever the lead,
   because a headline number that silently changes meaning is the exact class of
   fault the correctness rules exist to prevent; and switching lead must convert
   the income values, since flipping to a 40,000 to 300,000 euro range is not
   the mirror of the Canadian one.
3. **#56 optional deductions.** Needs its design note first.

## Risks or decisions needed

- **#56 expands the modelled baseline, which `CLAUDE.md` makes a scope decision.**
  The owner chose it knowing that. The concern raised was that adding Austrian
  levers alone would swap one bias for the other, since Austrian optional
  deductions would cut Austrian tax with no Canadian counterpart. The resolution
  on record: both sides get levers and **every one defaults to off**, so today's
  headline comparison and every golden test are unchanged. A design note in
  `docs/design/` must land before the first lever.
- **Claude in Chrome is unavailable on this account.** The extension refuses to
  authorize: the feature is disabled by the ITNCC organization's administrator.
  Google Chrome was installed to try it and is being removed again. This is not
  a local fault and must not be worked around. The headless screenshot tool
  above is the replacement and needs no extension and no account permission.
- **The conversion default differs in kind between years, deliberately.** 2026 is
  not over, so its exchange rate default is a daily reference rate; 2025 is
  complete, so its default is the ECB annual average. When 2026 closes its
  default should become the annual average too, and `docs/ANNUAL_UPDATE.md` still
  does not say so. Unchanged from the last handoff.
- **Manitoba (#46) is closed but worth re-checking each year.** If the province
  resumes indexation, the CRA rates page becomes right by accident. Confirm
  against T4032MB rather than assuming the disagreement persists. Unchanged from
  the last handoff.
